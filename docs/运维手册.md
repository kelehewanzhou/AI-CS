# 运维手册

日期：2026-11-10（Asia/Shanghai）。常驻服务仅postgres/backend/nginx，迁移、导入、账号和清理由受控运维执行。

## 日常检查

每日检查manage.py status、外部/health/ready、磁盘和备份任务状态。每周做独立库恢复，核对记录数和外键。每月在兼容分支内升级安全补丁，重新锁定镜像/依赖并完成验收。Compose依赖只保证启动顺序，不提供运行期主动摘流；数据库故障由外部探测及人工处理。Nginx对上游连接错误返回503统一JSON。

```bash
python scripts/manage.py status
docker compose logs --since 24h --tail 200 backend nginx
docker compose exec postgres psql -U kglearn_admin -d kglearn -c "SELECT state,count(*) FROM pg_stat_activity GROUP BY state;"
```

不要打印env、Cookie、数据库URL或原始问题。访问日志仅含request_id、IP、方法、路径、状态和耗时，不含参数/正文；后端只记录路由模板和异常类型。Docker轮转限制10m×5并不能保证30天时间上限，目标机日志收集/清理策略须设最长30天。严禁把包含秘密的完整容器检查结果贴到报告。

## 自动备份与异机副本

每日02:00（Asia/Shanghai）执行，保留14个日备份、4个周备份，硬上限35天。脚本将库全部表及权限备份，使用同一导出快照计算校验清单；恢复需dump、counts、sha256三件套。

Linux目标机统一安装到/opt/kglearn，配置/etc/kglearn-backup.env（root可读）：GPG_RECIPIENT与BACKUP_REMOTE=user@独立备份机:/专用目录/。先导入并核验专家/运维提供的GPG公钥与SSH主机指纹、配置最小权限SSH凭据；私钥另机保管。

```bash
sudo cp scripts/systemd/kglearn-backup.* /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now kglearn-backup.timer
sudo systemctl start kglearn-backup.service
sudo systemctl status kglearn-backup.timer kglearn-backup.service
```

任务先本机备份，再将三件套打包GPG加密并scp到独立存储；任一步失败返回非零。把systemd失败状态接到学校现有告警渠道，不在业务系统新增告警平台。远端专用目录也必须配置35天最长保留；密钥过期、空间不足或上传失败不得记作备份完成。Windows目标机使用任务计划，选择中国标准时间02:00执行python scripts/manage.py backup --offsite，并提供bash/gpg/scp；不能按宿主机其他时区误排。

## 故障处理

发布失败先查看.runtime/deployment.json及失败服务日志，保留.runtime/maintenance，修复后重试deploy。确认没有仍在运行的发布进程后，方可人工解除崩溃遗留的deploy.lock；不能同时启动第二次发布。备份崩溃遗留.backup-running同理，核实pg_dump和快照连接已结束后清除。

ready=503时检查数据库连通、alembic_version和成功导入记录，禁止把live=200当成ready通过。502/503检查backend是否运行、DNS解析和数据库权限；网关运行时DNS会重新解析新backend地址。

登录429先核对真实IP、可信代理网段和NAT共享情况，等待Retry-After后重试；只在实测后调整限流阈值。禁止通过信任任意X-Forwarded-For规避限流。

连接池耗尽时先检查pg_stat_activity、长事务与慢查询，固定单worker，现有连接池5+5；不要未经容量评估增加worker/连接数。

## 数据保留与恢复后的清理

qa_records正文最多90天，由受控运维账号在批准的维护窗口执行到期清理；用户/事件/答题保留至试点结束180天，随后按批准用户名单和外键依赖清理。没有HTTP清理、角色修改或成绩导出接口。试点结束日期、学校政策与批准名单由项目负责人提供，不能由开发脚本猜测。

恢复历史备份后先重新执行当时已批准的到期清理，再开放服务，避免已删除数据回流。清理个人记录须依次处理sessions、learning_events、exercise_attempts再users，并保留匿名问答按90天清理。记录操作时间、批准单与行数，不记录学生密码/个人正文。

生产替换前必须有备份演练、教学专家确认、TLS/IP验证和[最终验收清单](最终验收清单.md)签字。RPO≤24h、RTO≤4h为待目标机实测目标，不能用临时小库耗时替代生产承诺。
