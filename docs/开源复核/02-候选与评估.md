## 第三步：先过七项硬门槛

“保留”表示复核已有依赖；不意味着备选已经通过本地验证。下表评估先于本轮接入记录/验证工具修改。

| 硬门槛 | 当前选择的事实与检验方法 | 结论 |
|---|---|---|
| 对应具体功能 | 实际调用点为 GraphVisualization、seed_import.validator、auth.service、tests、verify_browser、Compose | 已确认 |
| 许可证清楚 | npm/PyPI 元数据、安装包许可文本；MIT/BSD 保留署名，Apache 保留 LICENSE/适用 NOTICE；psycopg 的 LGPL 见允许清单 | 包许可补档后复验；本轮不改库源码 |
| 按文档本地运行 | 生产静态构建、100项回归；隔离 PostgreSQL/Nginx/浏览器验收 | 以第四步机器结果为准；Compose daemon 未通过 |
| 固定版本/tag/commit | Python 带哈希 lock，pnpm integrity lock，镜像 digest；官方元数据额外记录能解析的 source_commit | 包版本可复现；部分 tag 查询限流不伪造 commit |
| 数据去向和额外下载 | 前端请求本项目 API；后端数据库为 PostgreSQL；模板问答无 LLM。安装/构建访问 npm、PyPI、镜像源；Playwright 可下载浏览器；Next 构建遥测需显式关闭 | 加浏览器请求目的地实测；不把安装联网写成运行时外传 |
| 已知安全问题 | 本次 pip-audit 覆盖 Python 生产 lock；pnpm audit 覆盖 web lock | 两份报告无已知漏洞；不涵盖操作系统/镜像或保证安全。备选未审计，不接入 |
| 栈/库/部署兼容 | 静态导出、FastAPI schema、同步 SQLAlchemy/psycopg 与数据库最小权限保持；无新数据库或运行服务 | 原生验收后确认；Linux/容器仍待验证 |

Compose 在“本地容器启动”门槛上尚未通过，因此仅保留既有部署配置，不能标记为正式目标环境准入。生产教学数据批准也不是组件库测试能够替代的事项。

## 软比较与最小接入方案

已选组件均有官方文档与上游测试源码，包发布日期和仓库维护时间在机器元数据中逐项保存。上游测试存在不代表本机运行过上游完整测试；本次运行的是本项目的真实需求验收。某些仓库维护信息因限流未取回，不能写成“仍活跃”或“已停更”。备选仅完成有界资料比较，没有安装或运行。

依赖面优先复用已有包：不新增 Sigma、jsonschema、pwdlib、Hypothesis、Selenium、podman-compose。生产依赖由两个锁文件管理；Python 开发测试工具目前由 CI 固定版本安装，未有完整带哈希开发依赖锁，是后续可改进项。

配置/错误处理沿用 common.config、common.errors、Nginx JSON 错误和 request_id；用回归检查错误不泄露密钥。Next/TestClient 的弃用提示作为兼容性债务记录，不未经核实添加替代包。

替换与退出成本：Cytoscape 主要改 GraphVisualization；Pydantic 涉及导入模型和 API schema，较高；Argon2 更换必须保留旧哈希校验/渐进再哈希，不能重置全部密码；SQLAlchemy/psycopg 涉及 repository 和事务，较高；pytest/Playwright 仅影响测试；Compose 替换涉及镜像、健康检查、迁移/导入/备份和发布顺序，较高。停更时可短期锁定版本继续复现，但必须持续复查漏洞与运行时兼容性。

本轮决定：继续使用已实测的现有成熟组件，补许可与可追溯清单、补运行数据目的地检验和维护说明。普通图形组件直接使用；数据库保留 repository，导入保留 validator，认证保留 AuthService。外部 LLM 未接入，无需提前添加空 LLMProvider。备选不纳入允许使用清单。
