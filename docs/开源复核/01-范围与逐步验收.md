# 当前环境开源复核：范围与逐步验收

核查日期：2026-11-20（Asia/Shanghai）。依据用户指定的《开源复用与 Vibe Coding 开发建议》执行。本轮是对既有系统的补查，不是重新开发系统。附件中的示例任务、签字栏和建议不等同于用户的额外授权，也不作为已经完成的证据。

## 第一步：固定本轮边界

首版闭环：浏览知识 → 查看跨课程关系 → 查看证据 → 做题 → 保存自己的学习记录。保留现有模板问答、学生/教师两种角色、CLI 数据导入和教师只读验收页。

技术栈以实际清单为准：Python 3.13.9、FastAPI 0.162.0、Pydantic 2.14.2、SQLAlchemy 2.0.57、psycopg 3.3.7、Alembic 1.20.1、argon2-cffi 25.1.0；Node 24.22.1、pnpm 10.34.9、Next.js 16.4.5、React 19.2.9、Cytoscape.js 3.34.4；PostgreSQL 17，部署保留 Docker Compose/Nginx。

业务规则以修订版架构、SOP 和代码为准：关系唯一来源为 knowledge_edges；ID、关系方向/对称性、证据状态、学习状态矩阵、不可变答题记录、本人数据隔离、数据库最小权限均不由第三方库决定。较早 MVP 说明中的“最近一次答对”等是历史建议，不能覆盖现有规则。

本轮不引入图数据库、重型 RAG、外部 LLM、教师编辑后台、班级模型或推荐系统。只补已有组件的来源、版本、许可、数据流、安全审计、评估、实测、允许清单和维护说明；必要时修复验收中发现的具体问题。

验收要求：

1. 清单与锁文件/实际安装版本一致，候选按硬门槛逐项记录，未知项不写通过。
2. 按模块保留少量候选，先评估、再在隔离环境运行已选方案；未运行的备选不获准接入。
3. 导入错误、图谱关系、权限隔离、答题持久化、问答边界和备份恢复实测；类型检查与静态构建通过。
4. 重要组件有实际许可证副本、替换点及启动/升级/回滚/移除说明。
5. Docker 构建、学校 TLS/网关、专家签字等未实测项保留为待办。

## 顺序与证据

| 步骤 | 完成条件 | 验证方式 |
|---|---|---|
| 1 固定边界 | 与现有配置和业务实现一致 | 读取 package.json、requirements.in/lock、Compose、导入器、验收规则及实际工具版本 |
| 2 少量候选 | 每个当前必要模块至少两个候选 | 官方仓库/包注册表查询，保存版本、许可、commit、来源和查询结果 |
