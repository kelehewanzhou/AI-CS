# 数据库权限配置说明

部署以 `database/init/roles.sql.inc` 和 `database/runtime_grants.sql` 为准。`python -m cli.migrate` 在迁移成功后自动应用权限；两个旧 `permissions.sql` 仅作为 psql 兼容入口引用同一脚本，不再维护独立授权。

| 角色 | 职责 |
| --- | --- |
| `kglearn_admin` | 数据库初始化、备份和恢复 |
| `kglearn_migrator` | 对象所有者，执行迁移、导入、账号创建和批准的到期清理 |
| `kglearn_app` | 后端运行，仅拥有下表列出的业务权限 |

| 对象 | `kglearn_app` 权限 |
| --- | --- |
| 全部业务表 | SELECT |
| `users` | 仅 UPDATE(password_hash, must_change_password, password_changed_at) |
| `sessions` | INSERT，及 UPDATE(revoked_at) |
| `exercise_attempts`、`learning_events`、`qa_records` | INSERT |
| 现有序列 | USAGE，用于事件、答题和问答记录编号 |

运行账号没有建表、内容写入、创建用户、DELETE、TRUNCATE、修改角色或修改答题记录的权限。用户及会话主键为 UUID，不需要用户编号自增序列。清理命令使用对象所有者连接，不能为运行账号追加删除权限。

## 部署与验证

全新数据库由 Compose 初始化脚本创建角色；迁移服务使用 `MIGRATION_DATABASE_URL`，后端使用 `DATABASE_URL`（角色 `kglearn_app`），密码均由环境注入。按[部署指南](部署指南.md)配置，不在命令中写明密码。

```bash
# 维护窗口：执行已有迁移并重新应用唯一权限脚本，确保使用当前发布镜像
 docker compose run --rm --no-deps migrate

# 表级授权；列级更新授权另见 column_privileges
 docker compose exec -T postgres psql -U kglearn_admin -d kglearn -c "SELECT grantee,table_name,privilege_type FROM information_schema.table_privileges WHERE grantee='kglearn_app' ORDER BY table_name,privilege_type;"
 docker compose exec -T postgres psql -U kglearn_admin -d kglearn -c "SELECT table_name,column_name,privilege_type FROM information_schema.column_privileges WHERE grantee='kglearn_app' AND privilege_type='UPDATE';"
```

已有旧数据卷不自动重建角色或修改对象所有者，须按部署指南备份并演练角色迁移。旧验收报告中的旧账号和授权清单只反映历史版本，不用于当前部署。PostgreSQL 集成测试 `test_runtime_privileges` 验证运行账号不能进行 DDL、删除答题、修改成绩及提升用户角色。
