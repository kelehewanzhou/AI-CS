# AI跨课程知识图谱学习系统 - 开发任务SOP总览

本文档包含完整的开发任务标准操作流程（SOP），基于《26.11.4AI跨课程知识图谱学习系统_总体技术架构设计_修订版_v2.0.md》编写。

## 文档说明

每个任务都包含：
- **本次只做什么** - 明确任务范围
- **明确不做什么** - 避免范围蔓延
- **要使用的字段和接口** - 技术规格
- **真实示例数据** - 可执行的样例
- **完成后的手工验收步骤** - 验收标准
- **需要补的测试和启动说明** - 测试要求

## 开发顺序

按以下顺序执行，每个任务完成并通过退出条件后，再开始下一个：

0. [任务0：工程基线与环境验证](./任务0_工程基线与环境验证.md) - 依赖锁定、目录结构、测试夹具
1. [任务1：公共设施+数据库迁移](./任务1_公共设施与数据库.md) - 建表、错误处理、健康检查
2. [任务2：seed_import CLI与校验](./任务2_导入与校验.md) - 数据导入、完整性检查
3. [任务3：auth模块与账号CLI](./任务3_认证与账号.md) - 登录、会话、密码管理
4. [任务4：graph只读服务与API](./任务4_图谱查询.md) - 子图查询、节点详情、关系展示
5. [任务5：exercise模块](./任务5_习题与答题.md) - 题目、判分、提交幂等
6. [任务6：learning模块与状态规则](./任务6_学习状态.md) - 事件记录、掌握度计算、教师摘要
7. [任务7：静态前端核心路径](./任务7_前端页面.md) - Next.js静态导出、Cytoscape图谱
8. [任务8：qa模块与问答面板](./任务8_模板问答.md) - 确定性匹配、模板答疑
9. [任务9：部署编排与正式验收](./任务9_部署与验收.md) - Docker Compose、Nginx、备份恢复

## 验收标准映射

每个任务对应架构文档中的验收测试（AT）：

- 任务2 → AT-01（导入幂等、错误报告）
- 任务4 → AT-02/03/04（子图查询、证据状态）
- 任务5 → AT-05（答题幂等、判分）
- 任务6 → AT-06（学习状态规则矩阵）
- 任务3/6 → AT-08（身份与权限）
- 任务7 → AT-09（完整用户路径）
- 任务8 → AT-07（问答基线17条）

## 预计工期

基于§7.2的串行开发顺序，预计8-10周：
- 任务0-2：1-2周（基础设施）
- 任务3-6：3-4周（核心业务）
- 任务7-8：2-3周（前端与问答）
- 任务9：1周（部署验收）

实际进度以各阶段退出条件为准，不以时间估算为硬性要求。

## 使用说明

### 给AI的完整任务包

将对应任务的markdown文件内容完整提供给AI，包含：
1. 任务标题和编号
2. 全部六个章节的内容
3. 相关架构文档章节引用（如§2.3、§3.6）

### 验收与交付

每个任务完成后必须：
1. 执行"完成后的手工验收步骤"中的全部项目
2. 补充"需要补的测试和启动说明"中要求的自动化测试
3. 更新README或运维文档
4. 提交代码并标注任务编号

### 关键约束

- **不跳过任务**：后续任务依赖前置任务的表结构、接口契约和配置
- **不扩展范围**：严格遵守"明确不做什么"
- **不猜测字段**：使用架构文档§2.3和§3的完整字段定义
- **不混用技术栈**：遵守§5.1的版本锁定
