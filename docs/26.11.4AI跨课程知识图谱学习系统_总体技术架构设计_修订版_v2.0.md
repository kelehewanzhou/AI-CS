### 1.2 业务目标与 P0 边界

交付一条可重复验证的路径：登录 → 浏览跨课程子图 → 查看节点、方向与证据 → 提交习题 → 保存个人记录 → 查看可解释状态 → 获得模板答疑。

| 范围 | P0 冻结内容 |
|---|---|
| 课程 | 保留 DS、CO、OS、CN 四种课程编码；首批主题由教学专家选择，可先覆盖其中两门 |
| 内容规模 | 12—20 个确认节点、10—15 条关系、至少 10 道客观题；完整 91/68 为扩展目标 |
| 角色 | 学生、教师；无班级与组织隔离 |
| 查询 | 当前有效内容、课程与关键词筛选、最多两跳子图、关系与证据状态筛选 |
| 学习 | 每次有效提交独立留存；个人事件、答题历史和固定规则状态 |
| 答疑 | 标题/别名匹配和固定模板；无模型、Embedding、中文分词插件 |
| 教师能力 | 只读内容验收摘要：当前导入结果、内容数量、证据分布；不读取个人学习数据 |
| 内容更新 | 受控 JSON 文件经 CLI 校验、事务导入；已有内容按稳定 ID 更新或下线 |

P0 不存在编辑、导入、发布、回滚 HTTP 接口；不实现在线内容后台、班级看板、个人成绩导出、推荐、简答题批改、外部模型、Redis 或图数据库。下线标记仅用于保留历史引用，不是草稿、发布批次或版本系统。

## 模块拆分

### 2.1 总体结构与模块边界

采用分层单体：浏览器 → Nginx → FastAPI → PostgreSQL。Next.js 在构建阶段导出静态页面，运行阶段由 Nginx 提供页面与脚本；API 通过同源 `/api/v1` 访问。

| 模块 | 唯一职责与拥有的数据 | 对外能力 | 禁止承担的职责 |
|---|---|---|---|
| 前端 `web` | 页面、筛选、图谱绘制、表单、请求状态 | 固定页面和 API 客户端 | 判分、权限裁决、证据与掌握状态计算 |
| `auth` | 用户、会话、密码、角色与身份限制 | 当前用户、登录/退出/改密、账号 CLI | 接受客户端指定角色或个人数据归属 |
| `graph` | 读取课程、节点、关系，生成关系展示与证据摘要 | 子图、节点/关系详情、内容摘要 | 个人学习状态、写入内容、答题 |
| `exercise` | 题目学生视图、判分、答题事务、幂等 | 题目列表、提交、本人答题历史 | 返回判分视图、计算节点掌握状态 |
| `learning` | 查看事件、状态规则、教师内容验收摘要编排 | 本人事件与状态、教师只读摘要 | 班级或个人成绩统计、写入答题 |
| `qa` | 确定性匹配、证据选择、模板回答、问答记录 | `QAService.ask` | 修改图谱、调用外部模型、推断掌握度 |
| `seed_import` | JSON 解析、全量检查、导入互斥与生命周期 | CLI、导入报告 | HTTP 导入、常驻任务队列 |
| `common` | 配置、数据库连接、错误、request_id、日志 | 无业务规则的公共设施 | 收纳状态规则、万能仓储或跨模块业务流程 |

### 2.2 目录、依赖与事务边界

后端约定：`api/routers/` 是唯一 HTTP 路由位置，`api/schemas/` 保存对外 DTO；每个业务模块内部只有 `service.py`、`repository.py`、`models.py`、必要的 `rules.py`。`rules.py` 中，学习规则只属于 `learning`，关系字典只属于 `graph`，判分只属于 `exercise`。`cli/` 提供 seed-import、accounts、cleanup 命令。

依赖方向固定如下：

- `api → auth / graph / exercise / learning / qa`，节点详情由 API 编排组合三个模块的返回值。
- `qa → graph`；`learning → graph` 用于确认请求的节点和内容摘要；`graph` 不依赖 `learning` 或 `exercise`。
- `exercise` 自己读取题目及其关联；不调用学习状态计算。`seed_import` 使用模型和校验规则，不经 HTTP，也不调用学习写服务。
- 模块写入只能经过本模块 service。`learning.repository` 可通过显式 SQL 只读联查题目、关联和答题，用于聚合；不导入其他模块 repository，不写其数据。
- repository 是普通查询函数，返回明确结构，不建立通用 CRUD 基类、仓储接口与实现类两套体系。

写事务由 service 开启和提交，repository 不自行提交。练习提交、事件写入、改密分别为独立事务；导入是另一个独立事务。查询时需要多个聚合口径一致的节点详情、状态和教师摘要，使用一次只读 `REPEATABLE READ` 事务共享连接，避免导入切换期间混读。事务不跨 HTTP 请求。

前端固定页面：`/login/`、`/graph/`、`/node/?id=CO03`、`/edge/?id=E001`、`/exercise/?id=Q001`、`/learning/`、`/teacher/acceptance/`。不使用未知数量的动态路径 `/nodes/[id]`。页面初始化先请求 `/auth/me`，身份信息保存在内存，刷新后重新获取；不在 localStorage 保存会话令牌。

### 2.3 完整存储字典

以下为 P0 完整字段，不以“关键字段”代替可建表定义。未明确可空的字段均为 `NOT NULL`；未写默认值的字段必须由服务或导入器提供。`tz` 表示 `timestamptz`，数据库保存 UTC、界面按用户时区展示。数据库枚举采用 `text + CHECK`，不使用原生 ENUM，便于迁移。

内容表 `courses`、`knowledge_nodes`、`knowledge_edges`、`exercises` 均额外包含且仅包含这三个公共字段：`is_active boolean DEFAULT true`、`created_at tz DEFAULT now()`、`updated_at tz DEFAULT now()`。更新时 service/导入器显式设置 `updated_at`；幂等跳过不改时间。

| 表 | 字段及类型 | 主键、外键与检查 |
|---|---|---|
| `users` | `user_id uuid`（服务生成）；`username varchar(64)`；`password_hash text`；`role text`；`is_active boolean DEFAULT true`；`must_change_password boolean DEFAULT true`；`created_at tz DEFAULT now()`；`password_changed_at tz NULL` | PK user_id；UNIQUE username；username 仅小写 ASCII 字母/数字/下划线，3—64 位；role 为 student/teacher；不存姓名、学号、手机号 |
| `sessions` | `session_id uuid`；`user_id uuid`；`token_hash char(64)`；`created_at tz DEFAULT now()`；`expires_at tz`；`revoked_at tz NULL` | PK session_id；UNIQUE token_hash；FK user_id → users；expires_at > created_at；用户停用、过期或 revoked_at 非空即失效 |
| `courses` | `course_code varchar(2)`；`name varchar(100)`；`textbook_info text DEFAULT ''`；加公共字段 | PK course_code；仅 DS/CO/OS/CN |

### 2.4 证据与关系约束

`evidence_detail` 若非空，只允许对象 `{book_title,edition,chapter,pages}`，四个值均为字符串，不保存教材原文。已核验要求四项 trim 后均非空；部分定位要求 book_title 非空且 edition/chapter/pages 至少一项非空；待补充允许 null 或不完整对象。数据库 CHECK 覆盖状态与对象类型、已核验必填值，导入校验器同时检查全部细项。书名与页码齐全只是技术条件，是否真实核验由教学专家负责，导入器不伪称完成教材核验。

节点不单独录入证据状态。根据所有当前有效关联边取最弱状态：存在待补充 → 待补充；否则存在部分定位 → 部分定位；否则有边 → 已核验；无边 → 待补充，并返回 `evidence_reason=no_relations`。节点响应同时返回各状态数量与来源边 ID，表示“关联关系证据覆盖”，不表示节点摘要已经教材核验。

关系展示必须由后端生成：prerequisite 为“source 是 target 的前置知识”、implements 为“source 实现/支撑 target”，二者 `display_mode=directed`；contrast 为“source vs target”、boundary 为“source 与 target 的边界”，二者 `display_mode=symmetric`。对称关系按 source_id < target_id 存一条；导入器规范化端点并拒绝同类型重复无序对。有向关系同 source、target、type 也不得重复，数据库唯一索引约束两类情况。图谱遍历可双向走边，不改变存储的关系方向。

## 模块接口契约（入参/出参）

### 3.1 通用 HTTP 约定与错误模型

业务路径统一前缀 `/api/v1`；仅登录、健康检查和幂等退出不要求已有有效会话。成功为 `{data:T,request_id:string}`；request_id固定32位小写十六进制，与Nginx原生请求ID一致。失败为 `{code,message,request_id,details?}`。`details` 只包含可公开的字段路径、原因和限制，不包含堆栈或密码。未知请求字段一律拒绝，查询重复项仅在明确声明数组时允许；ID、字符串长度和枚举以本节为准。问题/关键词归一化后为空也按422拒绝。

| code | HTTP | 适用范围 |
|---|---|---|
| VALIDATION_ERROR | 422 | 类型/枚举/长度错误、缺少字段、非法组合、子图超限 |
| UNAUTHENTICATED | 401 | 未登录、会话无效、登录账号或密码不正确；登录不区分账号是否存在 |
| FORBIDDEN | 403 | 角色不符、Origin/CSRF 不通过、必须改密但访问业务接口 |
| NOT_FOUND | 404 | 请求中的具体内容 ID 不存在或已下线；他人记录 ID 也按不存在处理 |
| CONFLICT | 409 | 同一提交 ID 配了不同题目或答案、并发状态冲突 |
| RATE_LIMITED | 429 | 登录限流，附 Retry-After |
| INTERNAL_ERROR | 500 | 未预期服务内部异常，包括 QA 生成异常 |
| UNAVAILABLE | 503 | 数据库或必要存储不可用、就绪检查失败 |

错误码保持这 8 个稳定值，登录限流与依赖不可用保留独立语义。注册 FastAPI 的请求校验、HTTP 异常和兜底异常处理器，覆盖默认 422 结构；Nginx 的 429 和 API 代理 502/504 也转换为统一 JSON（后两者对外为 503 UNAVAILABLE）。`not_covered`、`insufficient_evidence` 是 200 业务结果。

每个受保护接口都可能返回 401、403（含改密限制）、422、500、503；下表列出额外分支。无命名资源的列表查询不存在 404 情形，空列表返回 200。所有本人记录接口只从服务端会话取 user_id，不接受请求中的 user_id 或 role。健康接口例外见 §3.2。

### 3.2 认证、健康与摘要契约

| 方法/路径 | 入参和校验 | 成功 data | 额外失败 |
|---|---|---|---|
| POST `/auth/login` | JSON `{username,password}`；username 按存储规则，password 1—128 字；必须是同源 JSON 请求 | `{user:{user_id,username,role,must_change_password},expires_at}`；设置 Cookie；200 | 401、422、429、500、503；不存在账号不返回 404 |
| GET `/auth/me` | 无业务参数 | `{user:{user_id,username,role,must_change_password},expires_at}` | 无资源 404 |
| POST `/auth/logout` | 空 JSON `{}`，校验 Origin | `{logged_out:true}`；200；撤销并清 Cookie | 已退出仍返回 200；无资源 404 |
| POST `/auth/password` | `{current_password,new_password}`；新密码 12—128 字且不同于旧密码 | `{password_changed:true,reauth_required:true}`；清 Cookie、撤销该用户全部会话 | 旧密码错误 403；无资源 404 |
| GET `/health/live` | 无参数、无鉴权 | `{status:"ok"}`，200；只判断进程 | 无参数/资源/未登录错误；进程不可达由代理返回 503 |
| GET `/health/ready` | 无参数、无鉴权 | `{status:"ready"}`，200 | 数据库连接、迁移版本或当前种子未就绪时 503；不返回数据库配置 |
| GET `/learning/summary` | 无业务参数；必须 teacher | `{content_scope:"current_seed",seed_checksum,last_import:{run_id,finished_at},counts:{courses,nodes,edges,exercises},edge_evidence_counts:{verified,partial,pending}}` | 学生 403；无可用导入结果 503；不接受 user_id/class_id |

摘要中的 last_import 指最近一次 succeeded，skipped 不覆盖当前导入标识。counts 仅计当前有效内容；不返回总用户数、作答人数、正确率、个人明细或匿名群体成绩，避免教师汇总扩成看板。

### 3.3 图谱查询与详情契约

公共 DTO：

- `GraphNode={node_id,title,course_code,evidence_status}`。
- `EvidenceOverview={status,reason,counts:{verified,partial,pending},edge_ids}`；reason 为 `incident_edges` 或 `no_relations`。
- `EdgeView={edge_id,source_id,source_title,target_id,target_title,relation_type,display_mode,display_label,mechanism,abc_grade,boundary_note,evidence_status,evidence_summary,evidence_detail}`；全部键必返，evidence_detail 可为 null，boundary_note 可为空字符串。
- `NodeContent={node_id,title,course_code,chapter_scope,description,aliases,scope_tags,evidence_overview,incoming_edges:EdgeView[],outgoing_edges:EdgeView[]}`。数组保留存储方向；对称边只在对应的一侧出现，页面据 display_mode 呈现，不复制边。

| 方法/路径 | 入参 | 成功 data | 额外失败 |
|---|---|---|---|
| GET `/graph/subgraph` | 参数与规则见下表 | `{nodes:GraphNode[],edges:EdgeView[],meta:SubgraphMeta}` | 中心节点不存在/已下线 404；非法组合、超限 422 |
| GET `/nodes/{id}` | id 遵循 node_id 规则，无查询参数 | `{node:NodeContent,exercise_count:int,learning:NodeLearningState}`；关联题目正文只由 /exercises 提供 | 节点不存在/已下线 404 |
| GET `/edges/{id}` | id 遵循 edge_id 规则，无查询参数 | `EdgeView` | 关系或任一端点已下线/不存在 404 |

子图参数：

| 参数 | 类型/默认 | 精确定义 |
|---|---|---|
| node_id | 可选，单个 ID | 有中心模式；可以与 course_code 组合，但中心必须属于该课程，否则 422 |
| course_code | 可选，DS/CO/OS/CN | 筛选初始节点集合，允许扩展到外课程节点；不作为结果节点的硬过滤 |
| q | 可选，1—100 字 | 按 §3.7 归一化后对节点标题/别名做子串搜索；与 course_code 取交集；禁止与 node_id 同时使用 |
| hops | 整数 1/2，默认 1 | 仅对有中心或有 course/q 的多起点搜索生效；无任何起点条件时不得显式传入 |
| relation_type | 可选重复参数数组 | 仅四种类型；缺省包含全部；在遍历前过滤边 |
| evidence_status | 可选重复参数数组 | 已核验/部分定位/待补充；缺省包含全部；在遍历前过滤边，不修改内容数据 |

遍历语义：有 node_id 时起点为该节点；无中心但有 course/q 时，所有符合条件的有效节点都是起点，按 node_id 排序；无 node/course/q 时为 overview，返回当前全部有效节点及过滤后的边，applied_hops=0。有起点时沿过滤后的入边与出边进行广度扩展，最多两层；最后返回可达节点之间全部符合条件的边（诱导子图）。起点是孤立点也保留；课程筛选必须保留跨课程端点。q 无命中返回空图；所有边必须拥有响应内的两端节点。

上限固定为 60 节点、120 边，不接受客户端提高；超限整次返回 422，details.reason=`subgraph_limit` 并提示缩小起点，不截断。`SubgraphMeta={mode,seed_node_ids,applied_hops,filters:{node_id,course_code,q,relation_types,evidence_statuses},node_count,edge_count,limits:{nodes:60,edges:120},truncated:false,seed_checksum}`；可选标量未传时为 null，枚举数组用实际生效的完整列表。

基于 §4.6 的**结构测试夹具**，以下是响应 data 的验收投影；实际响应仍须包含上述全部字段：

| 请求 | nodes 的 ID | edges 的 ID | meta 的关键值 |
|---|---|---|---|
| `?node_id=CO03&hops=1` | CO03、OS02 | E001 | centered；起点 [CO03]；applied_hops=1 |
| `?node_id=CO03&hops=2` | CO03、OS02、OS03 | E001、E002 | centered；起点 [CO03]；applied_hops=2 |
| `?course_code=CO&hops=2&relation_type=implements&evidence_status=已核验` | CO03、OS02 | E001 | filtered；起点 [CO03]；E002 在遍历前被过滤 |

### 3.4 学习事件、状态与历史契约

| 方法/路径 | 入参及校验 | 成功 data | 额外失败 |
|---|---|---|---|
| POST `/learning/events` | `{event_type,resource_type,resource_id}`；仅允许 view_node/node、view_edge/edge、start_exercise/exercise 三种配对；资源必须当前有效 | `{event_id,event_type,resource_type,resource_id,created_at}`，201 | 资源不存在 404；类型配对错误 422；submit_exercise 被拒绝 |
| GET `/learning/events` | 可选 event_type；limit 默认 20、1—100；cursor 可选不透明游标 | `{items:[{event_id,event_type,resource_type,resource_id,created_at}],next_cursor:null或string}`，200 | 非法或跨用户游标 422；无资源 404 |
| GET `/learning/status` | 可选重复 node_id，1—60 个且去重；不传表示全部有效节点 | `{items:NodeLearningState[],rule_version:"p0-first-distinct-v1"}` | 任一显式节点不存在/下线则整次 404 |

事件顺序为 `(created_at DESC,event_id DESC)`；答题顺序为 `(submitted_at DESC,attempt_id DESC)`。游标按该键续查，使用服务端签名，绑定当前用户、接口和过滤条件，不接受任意 SQL/offset 内容。事件允许重复留存；状态只判断对应查看事件是否存在，不统计浏览次数，StrictMode/刷新重复不改变状态。

`NodeLearningState={node_id,state,reason,has_viewed,total_attempt_count,evaluation_count,recent_window_size,recent_accuracy,latest_evaluation_correct,available_exercise_count,can_evaluate_mastery,rule_version}`。state 是“未学习/学习中/练习中/已掌握”；recent_accuracy 为 0—1 数值，无有效评估为 null；latest_evaluation_correct 无评估时为 null；can_evaluate_mastery 表示当前有效关联题数是否至少 3，不承诺撤销历史达成状态。

### 3.5 习题学生视图、判分视图与提交契约

| 项 | 冻结规则 |
|---|---|
| 单选 choice | options 为 2—6 个 `{key,text}`，key 是唯一大写 A—F，text 非空、最多 500 字；answer_key 是 JSON 字符串且必须属于选项；提交答案必须是字符串，trim 后转大写 |
| 判断 judge | options 必须 null，answer_key 必须 JSON boolean；提交答案严格为 boolean，不接受字符串“true/对”或数字 |
| 简答 short_answer | P0 导入和提交均拒绝；无 null 判分、无人工批改字段或入口 |
| 学生视图 ExerciseStudent | `{question_id,type,content,options,difficulty,related_node_ids,is_active}`；不包含 answer_key、内部判分字段或正确答案解析 |
| 服务端判分视图 | ExerciseStudent + answer_key，仅在 exercise.service 内使用，禁止 ORM 整行直接序列化 |
| 提交反馈 | 返回本人答案、是否正确、是否计入评估和通用复习提示；P0 不返回 answer_key 或包含正确选项的完整解析 |

| 方法/路径 | 入参及校验 | 成功 data | 额外失败 |
|---|---|---|---|
| GET `/exercises` | 可选 node_id、question_id；同时传则取交集；limit 默认 10、1—20；offset 默认 0、非负；按 question_id 升序 | `{items:ExerciseStudent[],total,limit,offset}`；仅当前有效题，200 | 显式节点/题不存在或下线 404；节点无题为空列表 |
| POST `/exercises/attempts` | `{question_id,answer,client_submission_id:UUID}`；answer 按题型，body 不接受 user_id/is_correct | `AttemptView`，首次创建 201，原样重试 200 | 题目不存在/下线 404；答案格式 422；提交 ID 冲突 409 |

`AttemptView={attempt_id,client_submission_id,question:ExerciseStudent,answer,is_correct,is_evaluation,submitted_at,feedback}`。answer 为本人标准化后答案；feedback 固定为“本次回答正确”或“本次回答有误，请复习关联知识节点”。历史查询可返回下线题，题目正文、答案和关联从创建起不可变，因此不额外复制题目全文快照。个人状态由 `/learning/status` 查询，不放入提交响应；幂等重试返回同一条答题，题目当前 is_active 可变化，不要求响应字节完全相同。

前端一次主动提交生成一个 UUID，网络重试和双击复用该 UUID，收到成功后才允许下一次主动练习生成新 UUID。后端事务先检查 `(user_id,client_submission_id)`：相同题目及标准化答案返回原记录；不同则 409。已存在的幂等结果优先返回，即使题目此后下线。

同一用户同一题提交采用 PostgreSQL 事务级 advisory lock 串行化，并保留两个唯一约束作为最终防线。仅第一条真实提交 `is_evaluation=true`，以后不同 UUID 的重做仍新增记录但为 false。幂等唯一冲突后回滚并读取已提交记录再比较；不能把不同请求的 payload 混用。提交事务内只写 attempts，不再写 submit_exercise 事件。

### 3.6 学习状态的闭合规则（C1，需教学确认）

评估口径采用**不同题目的首次提交**：一次提交归属于该题创建时固定的全部 related_node_ids；不会因导入而改归属。`N` 为该节点相关、is_evaluation=true 的答题数，`W` 为按 `(submitted_at,attempt_id)` 取最近 min(5,N) 条，`R` 为 W 的正确数/条数，`L` 为最新评估是否正确。比较使用整数 `正确数×5 >= 窗口条数×4`，避免浮点边界差异。

按下表顺序命中后停止，涵盖全部输入：

| 优先级 | 条件 | 状态 / reason |
|---|---|---|
| 1 | N≥3 且 R≥80% 且 L=true | 已掌握 / mastery_rule_met |
| 2 | N>0，其余任意情况 | 练习中；N<3 为 insufficient_distinct_questions，否则 L=false 为 latest_evaluation_wrong，否则 accuracy_below_threshold |
| 3 | N=0 且存在 view_node 或关联 start_exercise | 学习中；无有效关联题为 no_exercises，否则 viewed_or_started |
| 4 | N=0 且无上述事件 | 未学习 / no_activity |

补充约定：view_edge 不自动把两端改为已学习；有提交但没有浏览事件仍优先命中 1/2；重做不改变评估序列，但出现在 total_attempt_count 与历史。历史评估包括后续下线的题，不追溯改分。无题节点可学习但不能新达成已掌握。新增题可提供新的评估机会。

这是一项明确取舍：首次答错后重做答对会获得正确反馈，但不靠同题反复作答提高掌握状态；需要新增不同题目才能改变评估。状态仅是 P0 规则标签，不是考试成绩或可靠的能力测量。教学专家如要求“同题纠错后恢复掌握”，须另立重新测评规则，不能在开发时改用最后一次答题偷换口径。

首批至少指定一个核心节点有 3 道内容上确实相关的题、另一个测试场景具备 5 道题，以验证 80% 分支；不强行让 10 道题覆盖每个节点 3 次。其余节点显示可用题量和掌握条件不足，不承诺全部能变为已掌握。

|---|---|
| 无事件、无答题 | 未学习，R=null |

| T,T | 练习中，N=2，R=1，不再存在状态空洞 |

### 3.7 模板答疑规则、响应与验收基线

POST `/ask` 输入 `{question:string}`，trim 后 1—500 字；成功 200：`{status,reason,answer,used_node_ids,used_edge_ids,uncertainty_flag,boundary_note}`。所有键必返；三个状态固定为 answered / not_covered / insufficient_evidence。无资源路径参数，匹配未命中不返回 404。P0 不含 degraded 枚举；内部异常按通用 500/503 错误响应处理。

确定性规则：

1. 对问题、标题、别名均做 Unicode NFKC、casefold；标点及空白替换为空格并折叠，不直接拼接被标点分开的词。中文不分词。标题和别名 trim 后标准化不能为空，别名至少 2 字符；ASCII 纯字母/数字别名使用非字母数字边界匹配，避免 OS 命中 most。
2. 用完整标准化标题/别名做子串匹配，不做相似度与拆词。标准化后别名与其他节点的标题/别名不能重复，导入拒绝冲突。匹配跨度有包含关系时保留更长词；同一节点多个命中只算一次。
3. 按“标题命中优先、最长命中长度降序、node_id 升序”排序。最多处理两个节点；命中超过两个，返回 not_covered、reason=too_many_nodes，提示拆分问题，不随意挑两个回答。
4. 一节点：概念模式；从其全部当前有效关联边中选已核验边，按 edge_id 升序最多 3 条。没有已核验边，返回 insufficient_evidence；有则用该节点自编摘要与所选关系说明组合固定模板，明确不是教材原文。used_node_ids 包含目标节点和被引用边两端，去重后升序。
5. 两节点：关系模式；忽略问题词序，读取两节点之间的直接关系，不猜测多跳关系。关系关键词字典：prerequisite=前置/先学，implements=实现/支撑，contrast=比较/对比/区别，boundary=边界/职责。无关系关键词不限制类型；恰好一个类型命中则只选该类型；命中多类型返回 not_covered、reason=ambiguous_relation，提示一次指定一种。选定类型无直接边为 not_covered、reason=no_direct_relation；只有未核验边为 insufficient_evidence。
6. 两节点模式仅采用已核验的候选直接边，按 relation_type 字典顺序 prerequisite/implements/contrast/boundary、再 edge_id 排序，最多 3 条；不能把两节点各自与第三节点的关系拼成答案。模板始终使用存储方向和后端 display_label，用户反向提问不会反转事实。
7. 证据充足指至少有一条按上述规则选定的已核验边；部分定位与待补充不作为肯定回答的依据。answered 引用仅来自实际使用边及其端点，uncertainty_flag=false，boundary_note 汇总非空边界说明。失败业务结果 used IDs 均为空、uncertainty_flag=true，boundary_note 给出缺口；answer 分别明确未覆盖或证据不足。

问答加载与记录在同一个受控流程：每次从当前数据库查询小规模节点/别名和候选边，不维护进程级词典缓存，避免导入后的陈旧匹配。生成成功后写入 qa_records 并提交，再返回 200；记录写入失败返回 503，不先返回成功。正常容器日志不保存问题正文；QA 代码异常只影响本次请求，记录 request_id 和异常类型，其他图谱接口继续工作。数据库整体不可用不承诺图谱仍可用。

## 数据流图文字描述

### 4.1 浏览、练习和状态数据流

1. 浏览器加载 Nginx 提供的静态页面，调用 `/auth/me`；未登录进入登录页，must_change_password=true 时只展示改密入口。
2. 登录由 auth 验证哈希、建立数据库会话，浏览器只持有 HttpOnly 不透明 Cookie。以后业务请求由 auth 根据会话取得真实身份。
3. 图谱页发送起点、跳数和边过滤条件；graph 从关系表查询最多两层，返回节点、规范方向、证据状态、展示标签。前端只绘制结果。
4. 进入节点详情时，API 在同一只读事务中组合 graph.node、exercise.count、learning.states；页面成功展示后上报 view_node。状态可在事件成功后刷新，避免先显示再误判事件已经保存。
5. 练习页通过 `/exercises` 取得学生视图，开始练习上报 start_exercise。提交事务验证当前题、加锁、判分、插入 attempt；不在客户端判分，不写重复 submit 事件。
6. 提交成功刷新本人答题历史和状态。learning 查询首次提交的评估序列，按固定规则聚合；不写一张无法追溯的掌握度结果表。

### 4.2 答疑数据流

问题 → 会话和长度校验 → 当前有效节点/别名归一化 → 匹配并判断节点数 → 单概念或双节点直接关系检索 → 按证据状态筛选 → 确定模板和引用 → 写 qa_records → 返回 200 业务结果。

无匹配/歧义/无直接边 → not_covered；相关边存在但均未核验 → insufficient_evidence；代码异常 → 500，必要存储不可用 → 503。P0 不调用外部网络服务，不将异常伪装为“未覆盖”。P1 接模型时才增加 `LLMProvider` 与降级规则，P0 不预建空接口类。

### 4.3 种子文件协议

只接受 UTF-8 JSON，读取容忍 UTF-8 BOM；不接受 CSV、GBK 或 Excel 文件。四个文件固定为 `courses.json`、`nodes.json`、`edges.json`、`exercises.json`；每个文件是 `{schema_version:1,items:[...]}`。数组、多值字段采用原生 JSON array，不再发明分隔符。

| 文件 | 每项完整字段 |
|---|---|
| courses.json | course_code、name、textbook_info |
| nodes.json | node_id、course_code、title、chapter_scope、description、aliases、scope_tags |
| edges.json | edge_id、source_id、target_id、relation_type、mechanism、abc_grade、boundary_note、evidence_status、evidence_summary、evidence_detail |
| exercises.json | question_id、type、content、options、related_node_ids、answer_key、difficulty |

所有列出的键必须存在；可空字段显式填 null，空数组或空字符串仅限字典允许之处。数据库公共字段、会话、答题和导入状态不属于种子格式。未知键拒绝，重复 JSON object 键拒绝，顶层 schema_version 不符拒绝。每个 items 内主键去重，相关节点数组内部去重且至少 1 项。习题必须关联本批 nodes 中的节点，边两端必须在本批 nodes 中，避免旧库“碰巧有这个 ID”掩盖输入缺失。

错误报告为 `{file,item_index,json_pointer,line,column,code,message}`；语法错误提供准确 line/column，结构和语义错误提供文件名、数组序号和 JSON Pointer，line/column 为 null，不伪造语义错误行号。该定位口径同步回写需求。每次最多输出 100 个错误，报告 total_errors。教学人员用文本模板维护 JSON；需要表格编辑时，另建离线转换工具，不扩大导入器格式。

校验还覆盖：有效课程引用、节点课程前缀、空文本、所有枚举、证据跨字段条件、别名标准化冲突、无自环、关系去重、选项与 answer_key 类型、不可变字段、已退役 ID、外键和上限。结构测试 profile 允许不足正式数量；pilot profile 必须达到 §1.2 数量要求和至少一个核心节点 3 题覆盖，并在发布清单中标明教学确认记录位置。数量检查不代替教学确认。

### 4.4 导入生命周期与历史保护（R1）

导入文件表示**完整的当前有效集合**，不是增量补丁。节点、题目和关系 ID 不可复用；全部内容主键不物理删除，不允许退役 ID 重新出现。误下线属于数据修复，需要离线审批的数据库恢复或专门迁移，不通过普通导入复活内容。

| 对象 | 同 ID 允许修改 | 同 ID 禁止修改 |
|---|---|---|
| Course | name、textbook_info | course_code |
| Node | chapter_scope、description、scope_tags、aliases；只用于说明补充 | course_code、title；改名或概念调整使用新 ID |
| Edge | mechanism、abc_grade、boundary_note、evidence_status、evidence_summary、evidence_detail | source_id、target_id、relation_type |
| Exercise | 无；已存在题目行和关联集合完全不可变 | type、content、options、answer_key、difficulty、related_node_ids 全部不可修改；纠错创建新题 ID |

题目不可变是为保持历史判分、关联归属和题目展示一致；不再添加完整题目历史表。发现错题时下线旧题并创建新题，历史标明原判定，不静默重判。节点说明和边证据当前会更新，但题目语义与关联不变；P0 不承诺复现过去某次答疑的完整内容快照，qa_records 保留当时答案文本和引用。

导入步骤：

1. 在内存解析四文件、检查完整结构并规范化对称边。计算规范化 JSON 的 SHA-256：文件名固定排序、对象键排序、items 按主键排序、集合型字段排序、保留有序选项顺序、忽略缩进与 BOM；checksum 同时包含 schema_version，不包含操作时间。
2. CLI 使用固定项目 advisory lock，`pg_try_advisory_lock` 失败立即退出，防止两个导入并发。账号、内容导入不与应用请求抢用同一连接；服务异常关闭连接即释放锁。
3. 记录 running 的 import_runs 并提交一笔管理事务。开启内容写事务，在同一锁保护下校验数据库已有 ID 和不可变字段。
4. 与最近 succeeded 的 checksum 相同且有效集合校验一致时不更新任何业务行，写 skipped；不能因为历史上曾出现相同 checksum 就跳过，以免错误回到旧数据包。
5. 新 ID 插入；允许字段按 ID 更新；本包缺少的旧内容设 is_active=false。本包引用的课程/节点必须同时有效；下线先处理缺失边/题，再处理缺失节点/课程。关联表仅为新题插入，不删改旧关联。学生查询忽略下线内容，历史仍可引用。
6. 在一个事务中完成全部内容变更和 import_runs.succeeded 更新；任何错误回滚全部内容，再用独立事务记 failed 与定位信息；如果日志连接也失败，则 CLI 输出失败报告并返回非零，不宣称已保存日志。
7. 输出新增、更新、下线、当前有效数和证据分布。运行中被杀的 running 记录由下次获得独占锁后标为 status=failed、error_summary.reason=interrupted，不将半次导入当成功。释放锁。

“失败整批回滚”指业务内容，不禁止失败日志落库。重复导入不删学生答题、事件或会话；已有学生数据无需停机清空。P0 内容更新在维护窗口执行，发布程序先摘除 API 写流量、停止后端，再执行迁移与导入；读写双快照的在线发布流程不在 P0 实现。

### 4.5 账号、会话与运维数据流

账号由授权运维人员通过 CLI 导入 UTF-8 JSON（此为账号命令输入，不属于四文件内容包），字段仅 username、role；新建随机 16 字符临时密码，数据库仅保存 Argon2id 哈希。CLI 把凭据写入权限受限的一次性输出文件，不打印到常规日志。由项目负责人经学校认可的既有渠道单独下发，程序不自动发邮件或消息；发放结束删除输出文件。

首次登录须改密，must_change_password 用户只能调用 me、password、logout。忘记密码通过 CLI 重置并撤销全部会话，不做找回邮件。测试与生产不内置账号、不提供快捷登录或客户端选角色；开发测试账号只能通过显式 dev fixture 命令创建，非 development 环境拒绝执行。

服务端生成至少 32 字节随机会话令牌，只在 Cookie 发送原始值，sessions 存 SHA-256 摘要；固定 8 小时有效，不滑动续期。每次受保护请求联查当前用户是否有效。退出更新 revoked_at，停用用户立即失效；每日 CLI 删除过期/撤销超过 7 天的会话。Cookie 为 HttpOnly、SameSite=Lax、Path=/，测试/生产必须 Secure 并使用 HTTPS；仅 localhost 开发允许关闭 Secure。

### 4.6 五节点结构夹具与纸面闭环

以下为**拟新增结构测试夹具，不是已存在的种子文件，不作教学或教材事实确认**。正式种子交付要补齐至少 10 题和完整字段。测试可使用固定文本占位符，但不得把测试书目带入试点。

| 对象 | 固定测试输入 |
|---|---|
| 节点 | CO03=TLB（别名快表）；OS02=虚拟内存；OS03=页表；DS04=图遍历；CN05=OSPF路由；所属课程按前缀 |
| E001 | CO03→OS02、implements、已核验，测试 evidence_detail 的四项均非空 |
| E002 | OS03→OS02、implements、待补充，evidence_detail=null |
| E003 | DS04→CN05、prerequisite、部分定位，测试书名及章节非空 |
| Q001—Q005 | 五道结构单选题，选项 A/B、答案 A、difficulty=1，均关联 CO03 与 OS02；测试 content 为互不相同的非空文本 |

纸面推演：

1. 四课程+上述节点/边/题导入，报告 nodes=5、edges=3、exercises=5，证据分布 verified=1/partial=1/pending=1；节点 CO03 的证据覆盖已核验、OS02 因 E002 为待补充。
2. 相同 checksum 再导入，结果 skipped，旧 run 和答题不变。导入把 Q001 关联改为 OS03，整批失败；删去 Q001 则原题下线，其旧关联和答题仍存在。
3. CO03 的两跳查询返回 CO03、OS02、OS03；只保留已核验边后只能扩展到 OS02，与 §3.3 三个查询样例一致。
4. 用户 A 未浏览直接提交 Q001，client_submission_id=S1、answer=A，生成 attempt=1、evaluation=true；状态 CO03/OS02 都为练习中，N=1。
5. 原样重试 S1 返回 attempt=1；相同 S1 改成 B 返回 409。用新 S2 重做 Q001 生成新 attempt 但 evaluation=false，N 仍为 1。
6. 对 Q002、Q003 首次答 A，各生成有效评估，N=3、R=1，两个关联节点均为已掌握。该序列不依赖 view_node 事件。
7. 提问“TLB 和虚拟内存是什么关系”，使用 E001 正向展示；“页表是什么”因无已核验关联边返回证据不足。
8. 学生调用教师摘要为 403；用户 B 查询答题历史不能得到 A 的记录；请求强行加入 user_id=A 为 422。账号停用后旧 Cookie 立即得到 401。

以上为契约一致性推演，尚未执行软件或数据库集成测试；不能据此宣称系统已经实现或通过 AT 验收。

## 技术选型&理由

### 5.1 版本与库锁定

选择成熟分支并锁定具体依赖。下列包版本是编写时查询官方包元数据得到的候选基线，不代表组合已经集成验证；第一个工程任务需完成 clean install/build、依赖相容性与安全检查，再提交唯一锁文件，后续模块不得另选同类库。

| 层次 | 固定选择 | 实施约束与理由 |
|---|---|---|
| Python | 3.13 分支；镜像精确补丁和 digest 在工程基线提交锁定 | 支持现选后端依赖；不使用随机器变化的系统 Python |
| API | FastAPI 0.162.0、Pydantic 2.14.2、Uvicorn 0.54.0 | 明确请求/响应 DTO 和统一异常处理 |
| ORM/驱动 | SQLAlchemy **2.0.57 同步**、psycopg 3.3.7，同步 `postgresql+psycopg` | 不引入 SQLModel、asyncpg 或第二套 ORM；减少异步事务复杂度 |
| 迁移 | Alembic 1.20.1 | 独立一次性迁移命令；不在 worker 启动时跑迁移 |
| 密码 | argon2-cffi 25.1.0，Argon2id PasswordHasher | 不自写哈希；校验失败统一登录响应 |
| Python 依赖管理 | Python 随附 pip；使用 pip-tools 7.6.2 生成带哈希的 requirements.lock | pip 精确补丁写入构建工具清单；只维护一份生产解析结果 |
| Node.js | 24 LTS 分支，仅构建阶段使用 | 镜像补丁/digest 在基线提交锁定，无 Node 运行容器 |
| 前端 | Next.js 16.4.5、React/react-dom 19.2.9、TypeScript 5.9.3 | App Router + 静态导出；业务取数全在客户端 |
| 图谱 | Cytoscape.js 3.34.4，直接接入 React | 只采用该图谱库，不并列“或同类” |
| JS 包管理 | pnpm 10.34.9 | packageManager 固定版本、提交 pnpm-lock.yaml，CI frozen-lockfile |
| 数据库 | PostgreSQL **17** 分支，Debian 镜像 | 当前规模关系查询与事务足够；精确 minor 与镜像 digest 在基线锁定 |
| 网关/容器 | Nginx 开源版 1.30.6、Docker Engine + Compose v2 | 具体镜像 digest/CLI 版本写入部署清单；不用 Nginx Plus 功能 |
| 验证 | 后端 pytest + httpx，前端基础类型检查/构建，关键路径 Playwright | 仅覆盖规则、权限、事务与真实用户路径，不为简单 DTO 编写镜像实现式测试 |

不在文档中虚构未生成的锁文件或镜像 digest。版本主线、渲染、ORM/驱动及密码/会话实现已确定；第 1 阶段只允许在兼容分支内锁定工具/镜像补丁，需换主线时先改本表。生产部署禁止 `latest`、浮动依赖和构建时无锁升级。

官方依据：PostgreSQL 17 支持期至 2029-11-08，14 至 2026-11-12，故不再使用“14+”作为基线。[PostgreSQL 支持策略](https://www.postgresql.org/support/versioning/)。Node 24 的 LTS 状态及 Python 3.13 生命周期分别依据 [Node.js 发布表](https://nodejs.org/en/about/previous-releases)、[Python 支持版本](https://devguide.python.org/versions/)。包元数据依据 [PyPI FastAPI](https://pypi.org/project/fastapi/)、[PyPI SQLAlchemy](https://pypi.org/project/SQLAlchemy/)、[PyPI pip-tools](https://pypi.org/project/pip-tools/)、[npm Next.js](https://www.npmjs.com/package/next)、[npm Cytoscape.js](https://www.npmjs.com/package/cytoscape)；Nginx 版本依据 [官方下载页](https://nginx.org/en/download.html)。元数据查询日期为2026-11-04；工程锁文件另记实际生成日期。

### 5.2 渲染和同步执行约束

Next.js 固定 App Router、`output=export`、`trailingSlash=true`。构建只生成公共空页面壳，不把知识库、题目答案、用户信息或服务端密钥静态写入 HTML/JS。业务页面用 Client Components 取数；`useSearchParams` 的读取放在 Suspense 边界中，避免静态构建失败。Cytoscape 在浏览器 effect 或客户端动态加载中初始化，模块顶层不得访问 window/document。不使用运行时 SSR、Server Actions、Route Handlers、Next 鉴权中间件或 Next API 代理。

这意味着业务数据仍全部由后端登录校验，静态资源本身公开可下载。不能用前端重定向保护数据。固定路径加查询参数可让下线/新增节点无需重新生成动态路径。静态导出的功能限制以 [Next.js 官方说明](https://nextjs.org/docs/app/guides/static-exports) 为准。

所有涉及同步 SQLAlchemy/psycopg 的 FastAPI 路由、依赖采用普通 `def`，利用线程池执行；不在 async def 中直接调用同步仓储函数。会话为请求级，不跨线程并发共用；初始 1 个 worker、连接池 5、max_overflow=5，后续按实测调整。同步连接方式依据 [SQLAlchemy psycopg 文档](https://docs.sqlalchemy.org/en/20/dialects/postgresql.html#module-sqlalchemy.dialects.postgresql.psycopg)，路由执行方式依据 [FastAPI 并发文档](https://fastapi.tiangolo.com/async/)。

### 5.3 部署、迁移与启动顺序

常驻服务只有 `nginx`、`backend`、`postgres`。前端多阶段构建把 out/ 复制入 Nginx 镜像；开发期可以运行 next dev，但不加入试点拓扑。数据库仅内网暴露，外部入口仅 443（80 仅用于跳转/证书流程）。TLS 优先由学校网关终止；若网关不提供则本机 Nginx 终止，并保证外部始终 HTTPS。

固定编排：postgres healthcheck（pg_isready）成功 → migrate 一次性服务成功 → seed-import 一次性服务成功或 skipped → backend `/health/ready` 成功 → nginx 对外服务。Compose 对应采用 service_healthy 与 service_completed_successfully；迁移/导入不是 backend entrypoint 的每 worker 动作。账号 CLI 为独立运维步骤，重新部署不重置用户密码。

首次启动和维护发布由部署脚本执行同一编排；已有数据库更新先备份、切维护页、停止后端写入，再升级。迁移或导入失败则保持维护状态、修复后重试，不自动对数据库降级。Compose 的依赖条件只管启动，不提供运行期自动摘流；运行期由外部探测与人工处置，Nginx 只做被动上游错误处理，不宣称开源版提供主动健康探测。[Compose 启动顺序官方说明](https://docs.docker.com/compose/how-tos/startup-order/)。

### 5.4 数据安全和最小运维

- Cookie POST 请求统一要求 `Content-Type: application/json`，严格校验 Origin 与配置的外部 HTTPS origin 一致，缺失或不符拒绝；CORS 不允许跨域。此要求涵盖登录、退出、改密、答题、事件和答疑，不仅依赖 SameSite。localhost 开发单独列出允许 Origin，测试/生产不开放通配符。
- Nginx 对 `/auth/login` 按可信客户端 IP 配置 5 次/分钟、burst=5，不将密码或请求体写日志。网关存在时只信任配置网段的转发头，错误 IP 解析在部署演练检查。429 返回统一 JSON 与 Retry-After。试点共享 NAT 的阈值只可在实测后调整；P0 不宣称覆盖分布式暴力破解，有实际需求再补账号维度限流。
- `.env`、凭据、私密原始问题和备份不入库，只交付 `.env.example`；Nginx/后端日志不记录 Cookie、密码和请求正文。每个请求由网关生成 request_id并覆盖外部同名请求头后传给后端，所有 API 响应回传；直接内部健康请求缺失时由后端生成同格式随机ID。
- 全容器日志驱动配置 max-size=10m、max-file=5；日志记录 request_id、接口、状态、耗时、异常类型，保留最多 30 天。qa_records 保存问答正文最多 90 天，界面提示不输入个人信息；actor_key 用按月密钥 HMAC，不公开用户映射。P1 选取问题集必须先人工去标识，教师无记录读取/导出接口。
- 个人用户、事件、答题保留至试点结束后 180 天，再由受控 cleanup CLI 按批准清单按外键依赖删除；法律或学校有不同要求时先调整策略。保留期内不做个人记录删改接口；清理后不再承诺重算旧状态，再次参加试点使用新账号，避免局部删 attempt 改变首次提交口径。
- 每日 02:00（Asia/Shanghai）执行 PostgreSQL custom-format pg_dump；保留最近 14 个日备份和 4 个周备份，加密复制到独立备份机/存储，不能只放数据库宿主机或同一卷；只授予项目运维恢复权限。备份覆盖学生记录和种子表，密钥另行保管；备份最多保留 35 天，恢复旧备份后重新执行到期清理，避免个人数据永久回流。
- 试点前至少做一次独立库恢复、校验答题条数及抽样外键的演练；暂定 RPO≤24 小时、RTO≤4 小时，以实际恢复记录确认为准。每日备份失败必须进入项目运维的既有告警渠道，由部署配置接入，不在业务系统新建通知平台。

### 6.2 重要取舍与剩余风险

| 风险/取舍 | 本轮方案 | 剩余限制与触发条件 |
|---|---|---|
| 掌握规则偏保守 | 首次不同题评估、同题重做只反馈 | 首次错误不被同题重做覆盖；教学专家必须确认这一产品语义，否则另定重新测评 |
| 稀疏题库 | 只要求核心节点具备 3 题，其余展示题量不足 | 部分节点达不到已掌握是可解释结果；不能用虚假多关联凑数量 |
| 内容冻结与历史成本 | 题目不可变，修订创建新 ID，保留旧引用 | 存在错题时旧判定不自动重算；确需追溯重判则新增专门迁移和教学审批 |
| 节点说明可更新 | 当前查询读当前摘要，题目和概念 ID 固定 | P0 无完整历史内容/发布批次；不可宣称支持旧版本重现和在线回滚 |
| 证据不足导致低回答率 | 只有已核验关系参与肯定答疑 | 首批若没有真实核验边，正常 answered 可能为零；教学内容准备是上线前置条件 |
| 模板能力有限 | 最多两个命中节点、只回答直接关系 | 多跳推理、真正的语义意图与否定识别不承诺；上线必须标识为“知识图谱模板答疑” |
| 一节点证据最弱状态 | 概览按所有关联边取最弱，回答可引用其中已核验边 | 节点显示待补充但某条关系可回答并不矛盾，页面同时显示证据分布与引用 |
| P0 无班级隔离 | 教师只获内容验收摘要 | 若学校要求班级成绩可见，则先补班级模型再扩大权限，不能给 teacher 全表读取 |
| 同步单体共享数据库 | 规则少、部署简单，QA 无外网依赖 | QA 局部异常可隔离，数据库故障影响全部依赖库功能；不宣称服务级高可用 |
| 维护窗口更新 | 停写后迁移导入，保持学生历史 | 短暂不可用；无零停机发布承诺，失败保持维护并修复 |
| 账号开通与学校规则 | 默认本地账号数据库会话 | 若学校要求 SSO，暂停本地账号上线，先实现学校支持的协议接入；不并行做两套身份源 |
| 主版本锁定与安全补丁 | 保持主线、补丁经验证进入唯一锁文件 | 包版本元数据核验不等于漏洞审计或相容性测试；首次工程构建仍是硬门槛 |
| 学生数据保留 | 最小信息、90 天问答、试点后 180 天学习记录 | 学校正式保留要求未确认；不得默认长期保存或将问答直接当研究数据使用 |

## 开发优先级顺序

### 7.1 开始编码前的确认与环境验证

时间以项目启动日 D0 计算，不假定项目已经启动。第 3 个工作日前，项目负责人组织确认 C1 状态、C2 汇总和 I3 题型/答案反馈；第 5 个工作日前确认结构字段与首批内容清单；第 10 个工作日前教学专家确认正式节点、方向、证据和核心题量。确认记录与需求 v2.2 一起归档，空白签名不算完成。

等待教学内容确认期间允许使用 §4.6 测试夹具开发协议和导入校验，禁止把测试内容标为正式已核验。第 3 日需求规则未确认时可继续基础设施/认证和只读内容模块，暂不把状态与题型规则定为上线行为。

第 1 周完成目标环境最小部署演练，记录：Docker/Compose 是否允许；镜像与 pip/npm 源是否可达；不可达时是否提供受控镜像仓库或离线包；CPU/内存/磁盘；TLS 终止与可信代理网段；外部 origin；是否强制 SSO；学校已有的数据保护和上线审批要求。只有实际要求会改变方案时才补设计；本文件不臆定备案或接入条件已经满足。
