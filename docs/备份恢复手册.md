# 备份恢复手册

日期：2026-11-10（Asia/Shanghai）。脚本仅备份或恢复到独立演练库，永不默认覆盖主库。

## 备份

```bash
python scripts/manage.py backup
# 或容器内直接调用
docker compose exec -T postgres bash /opt/kglearn/backup.sh daily
```

使用PostgreSQL custom-format pg_dump -Fc，覆盖全部业务表及权限。pg_export_snapshot保证dump与counts在同一只读快照；在线备份期间正常新写入不会造成两者不一致。pg_restore --list、SHA256及快照行数/外键清单全部成功后才把临时文件移入backup/。umask=077，目录应仅允许运维访问。

每日文件同一日期覆盖、保留14份；周日产生周副本并保留4份。维护发布另生成唯一release备份，不占日备份配额；所有文件最多35天。异常中断可留下临时目录/锁，须确认相关进程已结束后人工清除。

每份备份必须同时保存file.dump、file.dump.counts、file.dump.sha256。異机加密传输命令与计划见[运维手册](运维手册.md)。本机backup/不能充当唯一备份。

## 独立库恢复演练

```bash
python scripts/manage.py restore /backup/kglearn_daily_YYYYMMDD.dump
# 自动化演练，明确允许替换演练库：
python scripts/manage.py restore /backup/kglearn_daily_YYYYMMDD.dump --yes
```

默认目标固定kglearn_restore_test；可通过容器RESTORE_DATABASE设置kglearn_restore_test_安全后缀，不能指定kglearn。先核对三件套SHA256和归档目录，再创建独立库，pg_restore --exit-on-error --single-transaction恢复为迁移账号所有权，原有应用权限随ACL恢复。对所有public表逐表比较备份快照计数，逐个外键检查孤立记录，任何差异返回非零。

记录开始/结束时间、文件摘要、users/exercise_attempts/learning_events等计数与外键结果，不公开个人明细。至少一次演练包含实际答题历史，不能仅恢复空库。真实执行记录见[演练记录](备份恢复演练记录.md)。

## 生产恢复与人工切换

生产恢复具有覆盖影响，须由项目授权运维确认具体备份和停机窗口。先创建维护标记并停止backend；目标机使用manage.py部署目录的.runtime/maintenance。保存当前库额外备份，核验备份时间是否满足RPO，并完整做独立库恢复。

确认抽样用户/答题/外键及到期清理后，由数据库管理员在无应用连接时将现主库改名保留，再将已核验恢复库改名kglearn；两次ALTER DATABASE不是一个可回滚事务，任一步失败都保持维护并人工处理。运行账号连接权限、所有权、schema权限和alembic版本必须再次核对。不要通过删除pgdata卷、自动alembic downgrade或down/up代替恢复。

恢复旧备份后先重做批准的90天问答/试点结束180天个人记录清理，防止旧数据永久回流。启用与该数据库版本兼容的镜像，重新跑维护发布及完整路径探测，通过后才解除维护。记录旧库保留/销毁计划与授权，不把历史库无限保留。

RPO和RTO以正式环境真实记录为准；本次仅验证小型隔离数据库，结果不能外推到正式数据量。
