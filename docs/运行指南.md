# 运行指南

## 任务九后的统一部署方式

完整Compose与维护发布使用[部署指南](部署指南.md)中的 `python scripts/manage.py init-env`、`deploy v1.0.0` 与 `create-account`。默认前端为http://localhost:8080，统一API前缀/api/v1由Nginx移除。postgres与backend不再映射宿主机端口，下文历史宿主机直连命令只适用于另行准备的开发数据库和匹配DATABASE_URL，不能直接使用Compose内网主机名postgres。

若只验证现有Compose中的迁移/导入/账号，优先使用容器CLI和manage.py入口，不把数据库生产端口对外开放。初始化密码由init-env随机生成，.env.example中的空值和占位连接串不能直接运行。开发直连前端需单独加入http://localhost:3000 Origin；生产只允许外部HTTPS Origin。所有POST（含退出）均发送application/json。

## 开发环境启动

1. 在项目根目录复制 `.env.example` 为 `.env`，修改数据库密码和会话密钥。
2. 启动 PostgreSQL：

   ```bash
   docker compose up postgres -d
   docker compose ps
   ```

3. 安装并锁定的 Python 依赖：

   ```bash
   cd backend
   python -m pip install -r requirements.lock
   ```

4. 执行任务一初始迁移：

   ```bash
   alembic upgrade head
   ```

5. 启动 API：

   ```bash
   uvicorn main:app --reload --port 8000
   ```

6. 验证存活检查：

   ```bash
   curl http://localhost:8000/health/live
   ```

`/health/ready` 还要求数据库中存在一次 `import_runs.status = 'succeeded'` 的种子导入记录。执行任务二导入：

```powershell
python backend/cli/seed_import.py `
  --courses fixtures/courses.json `
  --nodes fixtures/nodes.json `
  --edges fixtures/edges.json `
  --exercises fixtures/exercises.json `
  --operator "admin@example.edu.cn"
```

相同 checksum 的完整数据包会返回 `skipped`；内容发生变化时会执行新增、允许字段更新和缺失内容下线。错误报告会同时输出到终端，并在 `import_runs.error_summary` 保留最多100条定位信息。

## 任务三认证与账号

任务一迁移已经创建 `users` 和 `sessions` 表。确认根目录 `.env` 已配置 `ALLOWED_ORIGINS` 和 `SESSION_COOKIE_NAME` 后，在 `backend` 目录执行：

```powershell
python cli/accounts.py create --username student01 --role student
python cli/accounts.py create --username teacher01 --role teacher
```

命令只把 Argon2id 哈希写入数据库，并将一次性临时密码写入 `backend/tmp/credentials_YYYYMMDD.txt`。通过安全渠道发放临时密码后删除凭据文件。

启动 API 后，认证接口为：

- `POST /auth/login`：校验 Origin，创建 8 小时 HttpOnly 会话 Cookie。
- `GET /auth/me`：验证 Cookie 并返回 `UserContext` 和会话过期时间。
- `POST /auth/password`：校验旧密码、保存新密码并撤销该用户全部会话。
- `POST /auth/logout`：撤销当前会话；无会话时也返回成功。

本地开发环境使用 `http://localhost:3000` 作为允许的 Origin；生产环境应从 `ALLOWED_ORIGINS` 中移除本地地址。

## 任务四图谱查询

图谱接口复用已登录且完成首次改密的会话 Cookie：

- `GET /graph/subgraph`：支持中心节点、多起点课程/关键词筛选、1—2 跳 BFS、关系类型和证据状态过滤。
- `GET /nodes/{node_id}`：返回节点内容、证据概览、入边和出边，并组合当前有效 `exercise_count` 与当前用户 `learning` 状态。
- `GET /edges/{edge_id}`：返回关系端点、后端生成的 `display_label`、展示方向和证据详情。

登录并完成改密后，可按下面方式验证任务四基线：

```bash
curl "http://localhost:8000/graph/subgraph?node_id=CO03&hops=1" \
  -H "Cookie: kglearn_session=<token>"
curl "http://localhost:8000/graph/subgraph?node_id=CO03&hops=2" \
  -H "Cookie: kglearn_session=<token>"
curl "http://localhost:8000/graph/subgraph?course_code=CO&hops=2&relation_type=implements&evidence_status=已核验" \
  -H "Cookie: kglearn_session=<token>"
curl "http://localhost:8000/graph/subgraph?q=TLB&hops=1" \
  -H "Cookie: kglearn_session=<token>"
curl "http://localhost:8000/nodes/CO03" -H "Cookie: kglearn_session=<token>"
curl "http://localhost:8000/edges/E001" -H "Cookie: kglearn_session=<token>"
```

预期基线为：CO03 一跳得到 CO03、OS02 和 E001；两跳增加 OS03 和 E002；按 `implements` 与 `已核验` 过滤时只保留 E001。完整 AT-02/03/04 清单见 [`AT-02-04_图谱查询验收.md`](AT-02-04_图谱查询验收.md)。

## 任务六学习状态

任务六新增以下受保护接口：

- `POST /learning/events`：记录 `view_node`、`view_edge`、`start_exercise` 三类事件，POST 请求必须带允许的 `Origin` 和 `Content-Type: application/json`。
- `GET /learning/events`：按事件时间倒序查询本人事件，支持签名、绑定用户和过滤条件的 `cursor`。
- `GET /learning/status`：查询指定节点或全部有效节点的固定规则状态；状态只使用不同题目的首次答题评估。
- `GET /learning/summary`：仅教师可调用，返回当前种子内容计数和关系证据分布，不包含个人学习数据。

节点详情 `GET /nodes/{node_id}` 现在在同一只读请求中组合图谱内容、当前有效题目数和当前用户的学习状态。学习状态验收矩阵见 [`AT-06_学习状态验收.md`](AT-06_学习状态验收.md)。

认证测试使用 SQLite 内存数据库，不依赖本机 PostgreSQL：

```powershell
cd backend
pytest tests/ -v
```

## 任务八模板问答

任务一迁移已经创建 `qa_records`，无需新增迁移。保持数据库、种子夹具及完成首次改密的学生/教师账号可用后，启动 API 和前端：

```powershell
# 终端一，backend 目录
uvicorn main:app --reload --port 8000

# 终端二，web 目录；开发直连 API
$env:NEXT_PUBLIC_API_URL = 'http://localhost:8000'
pnpm dev
```

开发直连时根目录 `ALLOWED_ORIGINS` 须包含 `http://localhost:3000`，`ENVIRONMENT=development` 用于本地 HTTP Cookie。同源部署继续使用默认 `NEXT_PUBLIC_API_URL=/api/v1`，代理须将 `/api/v1/ask` 转发到 FastAPI `/ask`；Next.js 静态导出不提供 API Route Handler。

登录后进入 `/graph/` 的“知识问答”面板，输入“什么是TLB”或“TLB和虚拟内存是什么关系”。前端统一通过 `lib/api.ts` 发送 `{question}`，携带 Cookie，并从 `{data,request_id}` 中读取结果。面板展示“已回答 / 暂未覆盖 / 证据不足”，已回答结果的引用链接分别进入 `/node/?id=…`、`/edge/?id=…`。

直接调用后端示例（将 `<token>` 替换为开发会话 Cookie）：

```powershell
$headers = @{ Origin = 'http://localhost:3000'; Cookie = 'kglearn_session=<token>' }
$body = @{ question = '什么是TLB' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://localhost:8000/ask' `
  -Headers $headers -ContentType 'application/json; charset=utf-8' `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

问题 trim 后为1—500字，归一化后须包含有效文本。服务仅依据当前有效节点、别名和已核验边生成固定模板，不调用外部模型。每次业务结果先写入问答快照再返回；模板异常为500、记录写入或提交失败为503，错误响应使用统一错误码和请求编号。日志不记录问题正文或异常参数；问答表使用按 UTC 月份轮换的 HMAC 标识，不写明文用户 ID。

问答专项、全量回归和前端构建：

```powershell
# backend 目录
python -m pytest tests/test_qa.py -v
python -m pytest tests -q

# web 目录
pnpm exec tsc --noEmit
pnpm build
```

完整基线、异常注入和前端手工验收见 [AT-07 问答基线验收](AT-07_问答基线验收.md)。

## 常见问题

**数据库连接失败**

- 检查项目根目录 `.env` 中的 `DATABASE_URL` 和 `DB_PASSWORD`。
- 确认 PostgreSQL 容器已经显示 `healthy`。

**迁移失败**

- 检查数据库是否已经存在任务一之前的残留表。
- 使用 `alembic current` 查看迁移版本。

**就绪检查返回 503**

- 空库或只执行迁移时，这是预期结果。
- 任务二完成种子导入并写入成功的 `import_runs` 后，重新访问 `/health/ready`。
