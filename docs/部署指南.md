# 部署指南

日期：2026-11-10（Asia/Shanghai）。本指南对应任务九及架构§5.3/5.4，沿用既有DTO和表结构。

## 前置条件与部署入口

建议至少2核CPU、4GB内存、20GB磁盘。目标机须有 Docker Engine、Docker Compose v2（本次配置解析实测2.40.3）、Python 3.13及锁定后端依赖。Linux使用系统服务执行自动备份，Windows可用相同Python入口配置任务计划。不要在已有业务数据库上执行本仓库隔离测试。

```bash
python -m pip install --require-hashes -r backend/requirements.lock
python scripts/manage.py init-env
python scripts/manage.py check
python scripts/manage.py deploy v1.0.0
python scripts/manage.py status
```

init-env生成互不相同的三组随机数据库密码、64位会话密钥和本地配置，绝不覆盖既有.env，也不输出密钥。check通过Docker自身dotenv解析配置，校验URL/账号/密码一致、Origin、TLS与种子。不要执行env、docker compose config后把完整输出附入工单：这些输出含秘密。

默认开发地址 http://localhost:8080；只绑定宿主机127.0.0.1。开发模式导入fixtures结构夹具，不代表正式教学证据。首次也可先build再docker compose up -d；更新必须使用deploy。

## 五服务与接口边界

postgres健康 → migrate退出0 → seed-import成功/跳过退出0 → backend就绪 → nginx启动。migrate和seed-import正常为Exited(0)，不是需要持续运行的服务。全部服务日志轮转10m×5。

| 外部地址 | 后端地址/用途 |
|---|---|
| /api/v1/auth/* | /auth/*，登录/退出/改密/会话 |
| /api/v1/graph/subgraph | /graph/subgraph |
| /api/v1/nodes/*、edges/* | /nodes/*、/edges/* |
| /api/v1/exercises* | /exercises* |
| /api/v1/learning/* | /learning/* |
| /api/v1/ask | /ask |
| /health/*、/api/v1/health/* | /health/*，无登录限流 |
| /login/、/node/?id=CO03等 | Next.js out静态页面，刷新保留查询参数 |

Nginx覆盖外部X-Request-ID，生成32位小写十六进制编号；成功、后端错误、网关403/422/429/503都保持请求头/JSON编号一致。统一POST检查Origin和application/json；登录限流5次/分钟、burst=5、nodelay，429带Retry-After:12。突发可以接受初始请求加5个burst，不应把示例误读为精确“前5次”。

数据库不暴露5432、后端不暴露8000。backend为非root用户。kglearn_app没有DDL、内容写入、答题修改/删除或角色修改权限；迁移与导入使用kglearn_migrator；postgres管理账号仅初始化/备份/恢复。账号开通通过独立CLI，不在启动过程中重置密码。

## 正式环境

在.env设置ENVIRONMENT=production，ALLOWED_ORIGINS为准确外部HTTPS Origin（逗号分隔、无空格/路径/通配符），SEED_DIR=./seeds。教学专家审核流程与checksum命令见[种子说明](../seeds/README.md)。未确认或内容已变更，seed-import直接失败并阻止后端开放。

优先由学校网关终止TLS，向本机127.0.0.1:8080转发；跨主机网关须通过SSH隧道或修改绑定至专用内网地址并配置防火墙，只允许网关访问。NGINX_TRUSTED_PROXIES填写真实网关IP/CIDR，确认网关覆盖而非信任外部X-Forwarded-For，实测客户端IP和共享NAT限流。禁止0.0.0.0/0和::/0。

若本机终止TLS：

1. 将真实证书放到nginx/ssl/fullchain.pem和privkey.pem，限制私钥权限。
2. 设置NGINX_SERVER_NAME为证书域名、COMPOSE_TLS=1、NGINX_TLS=1、ALLOWED_ORIGINS=https://实际域名。
3. 执行python scripts/manage.py deploy v1.0.0；该入口自动合并docker-compose.tls.yml。手工Compose命令须同时提供两个-f参数。
4. 验证HTTP跳转、证书链、TLS1.2/1.3、Secure Cookie、真实客户端IP与所有页面。脚本探测使用--resolve指定本机IP，并实际验证证书，不用-k绕过。

## 维护更新

```bash
python scripts/manage.py deploy v1.1.0
```

顺序为配置/种子预检 → 构建 → 确认数据库健康 → 创建维护标记 → 停止backend写入 → 一致性备份 → 重建并等待migrate退出 → 重建并等待seed-import退出 → 启动backend并等待ready → 启动nginx并等待进程健康 → 解除维护并经代理探测。只在成功后持久化.runtime/release.env版本；状态与备份路径记录.runtime/deployment.json。

迁移/导入/就绪失败保留维护标记，停止backend，postgres与数据卷保留。修复后重跑同一命令。不得用down/up冒充数据库回滚；需要恢复时按[备份恢复手册](备份恢复手册.md)实施。失败发布使用本次构建的镜像只保留在本机，不宣称已发布成功。

## 账号与日常验证

```bash
python scripts/manage.py create-account student01 student
python scripts/manage.py create-account teacher01 teacher
curl --fail http://localhost:8080/health/live
curl --fail http://localhost:8080/health/ready
curl --fail http://localhost:8080/api/v1/health/live
curl --fail http://localhost:8080/login/
```

临时密码仅写credentials/credentials_YYYYMMDD.txt，安全发放后删除，禁止把文件发到代码库。首次改密撤销全部会话，用户须重新登录再进入graph，保持现有认证契约。

已有早期任务的pgdata若是由kglearn_user超级用户初始化，不能直接套用新账号假定角色已存在：先完整备份并在独立库演练，再由现有管理员创建新角色、将业务对象所有权交给kglearn_migrator、撤销public权限并执行runtime_grants.sql，随后修改URL。禁止删除数据卷“修复”角色问题；初始化脚本仅在空卷运行。

镜像与锁文件见[版本清单](版本清单.md)。当前验证和待办见[验收报告](AT-01至AT-09验收报告.md)。
